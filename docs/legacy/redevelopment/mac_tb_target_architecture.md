# MAC 100G Testbench Target Architecture

## Scope and invariants

This is the implementation contract for the AXI-reference migration.  All changes remain under `mac_100g`; `src/hdl_top` is out of scope.  The MAC TB must compile and run without AXI project paths, packages, filelists, scripts, or environment variables.

The existing MAC hierarchy is retained because it already separates protocol agents, testbench services, tests, and RTL:

```text
src/hvl_top/
  pkg/                 package assembly, configuration, utilities
  mac_agents/          AXI4-Stream, RS, APB, reset agents
  tb/                  env, predictor, scoreboard, coverage, checker
  test/                base and feature tests
sim/Questasim/         MAC-local compile/run/regression orchestration
logs/                  generated compile, test, regression, summary logs
results/               generated per-run metadata and regression summaries
coverage/              generated UCDBs, merged UCDB, HTML reports
docs/                  architecture, inventories, migration/change reports
```

Only `docs/` is created in Phase 1.  `logs/`, `results/`, and `coverage/` are generated by the Phase 3–6 execution framework and ignored by Git.

## Scoreboard contract

`mac_reference_model_c` remains the MAC-specific prediction boundary:

```text
AXI TX monitor -> reference model -> expected RS FIFO --+
RS TX monitor  ----------------------------------------->+-> TX comparator

RS RX monitor  -> reference model -> expected AXI FIFO -+
AXI RX monitor ----------------------------------------->+-> RX comparator

reset monitor ----------------------------------------------> scoreboard reset policy
```

The refactored `mac_scoreboard_c` will retain separate typed analysis FIFOs and queues, but add a MAC-local configuration contract:

- `enable_tx_check`, `enable_rx_check`;
- field enables for addresses, EtherType, payload, FCS, and error indicators;
- explicit strict in-order matching as the only initial matching policy;
- bounded unmatched-frame timeout (disabled only when configured as zero);
- reset epoch/flush behavior driven by existing reset-monitor analysis events;
- expected-drop counters from the reference model for error/PAUSE frames;
- total, matched, mismatched, timed-out, flushed, and residual counters;
- component-scoped UVM IDs and structured expected/actual diagnostic output.

VLAN checking is deliberately deferred.  Current transaction objects and the reference model do not carry an explicit VLAN representation; inventing one here would change the MAC functional contract without requirements/test support.

## Configuration contract

`mac_tb_cfg_c` remains the owner of physical virtual interfaces and bootstrap state.  `mac_env_cfg_c` remains the owner of agent topology and feature selection.  Phase 2 will extend the environment configuration with checker policy only; test-specific overrides remain in tests/plusargs.

Classification rules:

- Protocol-defined values stay in MAC packages/types (for example PAUSE addressing, EtherType, preamble/SFD/FCS behavior).
- Environment policy belongs in `mac_env_cfg_c`.
- Test choices are set in the test class or supported plusargs.
- Run-framework paths and selection live in the Makefile/runner variables.

## Execution and reporting contract

The Makefile remains the public interface and will provide:

```text
make help
make compile
make run TEST=<test> [SEED=<seed>] [PLUSARGS="..."] [DEFINES="..."]
make smoke
make regression
make coverage
make clean
```

Variables: `SIMULATOR`, `TEST`, `SEED`, `PLUSARGS`, `DEFINES`, `SOURCE_DIR`, `LOG_DIR`, `RESULT_DIR`, and `COVERAGE_DIR`.

Every run gets a MAC-local run ID, deterministic paths, and a record containing `TEST`, `SEED`, `STATUS`, `ERROR_COUNT`, `WARNING_COUNT`, `LOG_FILE`, and `DURATION`.  Regression will preserve a nonzero exit status when any test fails and will emit a human-readable summary plus a machine-readable result file.

## Coverage contract

Keep existing observed-transaction covergroups and their configuration enable.  Add a MAC-local per-test UCDB location, merge target, HTML report location, and status reporting.  New bins/crosses require traceability to an available MAC requirement or an implemented transaction field; candidate VLAN, jumbo, IPG, reset-during-traffic, and configuration crosses are not added until that evidence exists.

## Validation order

1. Scoreboard: compile, smoke, deterministic TX payload test; inspect UVM fatal/error, scoreboard result, generated log, and RTL diff.
2. Logging/Makefile: help, compile, single run, smoke alias.
3. Regression: current four-test list with individual results and summary.
4. Coverage: supported test UCDB, HTML, merged report, and threshold status.
5. Every phase: AXI dependency scan and RTL no-change check.

## Non-goals

- No AXI protocol code or AXI file is copied.
- No RTL behavior is changed.
- No unsupported RX, VLAN, or jumbo-frame requirement is silently declared verified.
